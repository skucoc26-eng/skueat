# 카카오 사용자와 운영자 권한 관리

## 범위와 의존 순서

1. 직접 구현: User 테이블(고유 카카오 ID, 닉네임, 첫/최근 로그인, user/operator 역할), UserRoleChange 감사 테이블을 추가한다. 기존 AdminSession에 UserID(기존 별도 관리자는 0)를 추가해 카카오 운영 기능 세션을 구분한다. 리뷰·음식점·익명 이벤트는 변경하지 않는다.
2. 직접 구현: 카카오 콜백 성공 시 회원을 UPSERT한다. 최초 로그인은 user로 고정하고 재로그인은 기존 역할·최초 시각·내부 ID를 보존한다. 로그인마다 서버 관리 세션을 발급하고 이전 브라우저 관리 토큰을 폐기한다. 사용자 목록은 새 로그인부터 채우며 과거 로그인 일시는 추정하지 않는다.
3. 직접 구현: /api/admin/session과 보호된 리뷰·통계 API는 기존 별도 관리자 또는 DB role=operator이고 유효한 카카오 관리 세션인 사용자에게 허용한다. 카카오 운영자는 users/role/user-role-audit API를 사용할 수 없다. 권한 변경은 별도 관리자·Origin·CSRF 검증을 모두 거쳐 DB 트랜잭션에서 감사 기록과 함께 적용한다. 회수 시 해당 사용자의 관리 세션도 폐기한다. 로그아웃은 관리 토큰을 폐기하고 현재 브라우저의 로그인 정보를 지운다.
4. 직접 구현: /admin에 사용자 목록·검색·50개 페이지·운영자 지정/회수·최근 변경 이력을 추가한다. 운영자에게 해당 섹션은 표시하지 않는다. 카카오 로그인 링크의 복귀 경로는 /admin만 허용하며 외부 URL을 저장하거나 따라가지 않는다.
5. 직접 검증: 서비스·HTTP 테스트로 저장, 재로그인, 권한 경계, 회수, 쿠키 재사용, 입력 검증, 감사 실패 롤백을 확인한다. JS 테스트와 실제 브라우저에서 목록/권한 UI를 확인한다. 실제 카카오 인증 서버는 모의 응답과 구분해서 보고한다.
6. 직접 검증·배포: 운영 DB의 로컬 복사본으로 마이그레이션 전후 음식점·리뷰를 비교하고 운영 볼륨 스냅샷을 생성한다. 전체 테스트·빌드·diff 검토 후 푸시/자동 배포, 기존 관리자 로그인·사용자 조회·기존 데이터 보존을 확인한다. 운영 사용자를 임의로 승격하거나 검증 계정을 삽입하지 않는다.

## API와 권한

- GET /api/admin/users?page=1&search=... : 별도 관리자, 회원 50개/페이지와 total 반환. 항목은 내부 ID, 닉네임, 역할, 첫/최근 로그인, 전체 리뷰 수. 카카오 ID·토큰은 반환하지 않는다.
- POST /api/admin/users/:id/role : 별도 관리자 + CSRF/Origin, role은 user 또는 operator만 허용.
- GET /api/admin/user-role-audit : 별도 관리자, 최근 50개 역할 변경(대상 내부번호, 변경 전/후 역할, 관리자, 시각).
- 기존 /api/admin/stats, reviews, audit, moderation : 별도 관리자 또는 운영자. 리뷰 변경의 행위자는 별도 관리자명 또는 operator:<내부 ID>로 구분.
- 기존 /api/admin/session : authenticated, owner 필드로 관리 화면/사용자 관리 화면을 구분.
- 익명 이용 통계는 회원별 행동 추적으로 전환하지 않는다. 운영자 활동은 관리자와 동일하게 집계에서 제외한다.

## 테스트 입력과 기대 결과

- 같은 카카오 ID로 두 번 로그인 → User 1개, 동일 내부번호·첫 로그인, 새 닉네임·최근 로그인, 기존 operator 역할 유지. 임의 역할 입력으로 최초 계정이 승격되지 않는다.
- 잘못된 OAuth state / 잘못된 카카오 ID / DB 저장 오류 → 로그인 완료·새 로그인 쿠키 발급 없음.
- 익명 → 관리 API 401. 일반 카카오 사용자 → 관리 API 403. 운영자 → 리뷰/통계 200, 사용자/역할/역할이력 403.
- 별도 관리자 역할 부여 → 해당 브라우저의 다음 관리 요청 허용. 회수 → 다음 요청 403, 기존 관리 세션 삭제. 다시 부여해도 폐기된 관리 토큰은 복원되지 않는다.
- 권한 변경 CSRF 오류 403, 잘못된 역할/번호/본문 400, 없는 사용자 404, DB 감사 기록 실패 시 역할 변경도 롤백.
- 운영자 로그아웃 → 복사 쿠키로 관리 API 접근 거절. 운영자와 별도 관리자 감사 행위자 구분.
- 닉네임 검색·내부번호 검색·페이지/검색 길이 한도·등록 리뷰 수를 확인. 별도 관리자는 모든 변경 이력을 볼 수 있다.
- 사용자 목록 응답 순서가 역전되어도 최신 필터 유지. 닉네임은 textContent로 출력한다.
- 실제 SQL 오류를 발생시켜 로그에 세션 토큰/매개변수가 출력되지 않고 오류 자체는 기록되는지 검증한다. 정상 사용자 권한 조회의 0개 결과를 SQL 오류로 기록하지 않는다.
- 레거시 로그인 쿠키만으로 운영자 권한을 얻을 수 없다. 기존 쿠키의 일반 리뷰 작성은 기존 유효기간 동안 유지한다. 새 관리 기능을 쓰려면 카카오 재로그인이 필요하다.
